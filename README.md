# season_report — генератор отчёта КХЛ по интернет-аудитории

Сервис берёт **структуру** официального отчёта КХЛ (по образцу) и генерирует
новый отчёт за выбранный сезон: тянет данные из Яндекс.Метрики и пишет
аналитический текст каждого раздела через Claude — в той же деловой тональности.
Результат — файл `.docx`.

Никаких плейсхолдеров: структура задаётся кодом (`structure.py`), а текст
пишется заново под новые цифры.

## Как это устроено

```
Яндекс.Метрика ──► данные по разделам ──┐
                                        ├──► сборка .docx (по структуре образца)
структура отчёта + стиль ──► Claude ────┘        ▲
(пример прозы из образца)   пишет текст           данные + текст
```

Разделы (Приложение №1 — аудитория сайтов КХЛ), в порядке образца:
совокупные показатели · география по странам · география по регионам РФ ·
демография (возраст) · распределение по полу · ТОП-10 интересов (аффинити) ·
источники трафика · переходы из соцсетей · устройства · операционные системы.

## Установка

```bash
pip install -r requirements.txt
cp .env.example .env   # впишите токен Метрики, ID счётчика и ключ Anthropic
```

- OAuth-токен Метрики: https://oauth.yandex.ru/
- Ключ Anthropic: нужен для генерации текста (раздел `ANTHROPIC_API_KEY`).

## Запуск

```bash
# за текущий сезон КХЛ (1 июля — 30 июня), с аналитическим текстом
PYTHONPATH=src python -m yandex_report.cli

# конкретный период и метка сезона
PYTHONPATH=src python -m yandex_report.cli \
  --date-from 2024-07-01 --date-to 2025-06-30 --season 2024/2025 \
  --output output/khl_2024_2025.docx

# черновик без текста (только заголовки и таблицы) — ключ Anthropic не нужен
PYTHONPATH=src python -m yandex_report.cli --no-llm
```

Готовый файл появится в `output/`.

## Структура проекта

```
src/yandex_report/
  config.py          # чтение .env (Метрика + Anthropic + модель)
  metrika_client.py  # клиент Reporting API Метрики
  report_data.py     # запросы + агрегация по разделам (DataBlock)
  structure.py       # СТРУКТУРА отчёта: разделы, заголовки, примеры стиля
  report_writer.py   # генерация текста разделов через Claude
  docx_builder.py    # сборка нового .docx из структуры/данных/текста
  cli.py             # точка входа
samples/             # образец отчёта, из которого взята структура
tests/               # тесты на сбор данных и сборку docx
```

## Как менять структуру или стиль

Всё — в `src/yandex_report/structure.py`:

- **порядок и заголовки разделов** — список `SECTIONS`;
- **о чём писать** в разделе — поле `guidance`;
- **тональность** — поле `style_example` (абзац-образец, который Claude берёт
  как ориентир по манере, не копируя факты);
- **какие данные** питают раздел — поле `data_key` (собирается в `report_data.collect`).

## Ограничения

Яндекс.Метрика покрывает **интернет-сайты** КХЛ (Приложение №1). Разделы
образца по мобильному приложению (AppMetrica / Google Analytics) и по Клубам
КХЛ (отдельные счётчики) требуют других источников и в этот отчёт не входят —
их можно добавить, расширив `structure.py` и `report_data.py`.
