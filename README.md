# season_report — генератор отчёта КХЛ по интернет-аудитории

Сервис берёт **структуру** официального отчёта КХЛ (по образцу) и генерирует
новый отчёт за выбранный сезон: тянет данные из Яндекс.Метрики и пишет
аналитический текст каждого раздела через Claude — в той же деловой тональности.
Результат — файл `.docx`.

Никаких плейсхолдеров: структура задаётся кодом (`structure.py`), а текст
пишется заново под новые цифры.

## Как это устроено

```
Яндекс.Метрика ──► данные по разделам ──┐
                                        ├──► сборка .docx (по структуре образца)
структура отчёта + стиль ──► Claude ────┘        ▲
(пример прозы из образца)   пишет текст           данные + текст
```

Разделы (Приложение №1 — аудитория сайтов КХЛ), в порядке образца:
совокупные показатели · география по странам · география по регионам РФ ·
демография (возраст) · распределение по полу · ТОП-10 интересов (аффинити) ·
источники трафика · переходы из соцсетей · устройства · операционные системы.

Каждая таблица содержит колонку **«Изменение»** — динамику к прошлому сезону
(данные собираются через comparison-эндпоинт Метрики, текущий сезон против
предыдущего), и текст разделов отражает рост или снижение показателей.

## Установка

```bash
pip install -r requirements.txt
cp .env.example .env   # впишите токен Метрики, ID счётчика и ключ Anthropic
```

- OAuth-токен Метрики: https://oauth.yandex.ru/
- Ключ Anthropic: нужен для генерации текста (раздел `ANTHROPIC_API_KEY`).

## Запуск

```bash
# за текущий сезон КХЛ (1 июля — 30 июня), с аналитическим текстом
PYTHONPATH=src python -m yandex_report.cli

# конкретный период и метка сезона
PYTHONPATH=src python -m yandex_report.cli \
  --date-from 2024-07-01 --date-to 2025-06-30 --season 2024/2025 \
  --output output/khl_2024_2025.docx

# черновик без текста (только заголовки и таблицы) — ключ Anthropic не нужен
PYTHONPATH=src python -m yandex_report.cli --no-llm
```

### Из CSV-выгрузок Метрики (без API)

Если API упирается в лимиты — можно выгрузить данные вручную в интерфейсе
Метрики («Экспорт → CSV») и построить отчёт из файлов. Для каждого раздела —
два файла (текущий и прошлый сезон); диапазон дат в имени файла определяет,
какой из них текущий. Токен Метрики при этом не нужен.

```bash
PYTHONPATH=src python -m yandex_report.cli --from-csv samples/csv --season 2025/2026
# или перечислить файлы: --from-csv a.csv b.csv c.csv
```

Распознаются выгрузки с первым столбцом: «Интервал дат визита» (сводка),
«Страна», «Регион»/«Город», «Возраст», «Пол», «Источник трафика»,
«Социальная сеть», «Тип устройства», «Операционная система».

Готовый файл появится в `output/`.

## Веб-версия на Vercel

В проекте есть готовое веб-приложение: форма выбора сезона + serverless-функция,
которая тянет Метрику, пишет текст через Claude (разделы генерируются
параллельно, чтобы уложиться в лимит времени) и отдаёт `.docx` на скачивание.

```
public/index.html   — форма
api/generate.py     — serverless-функция (GET /api/generate)
vercel.json         — runtime, maxDuration=60, бандлинг src/
```

### Деплой

1. Импортируйте репозиторий в Vercel (New Project → выбрать репозиторий).
2. В **Settings → Environment Variables** задайте:
   - `YANDEX_METRIKA_TOKEN` — OAuth-токен Метрики;
   - `YANDEX_METRIKA_COUNTER_ID` — ID счётчика;
   - `ANTHROPIC_API_KEY` — ключ Anthropic;
   - `REPORT_MODEL` *(необяз.)* — модель, по умолчанию `claude-opus-5`;
   - `REPORT_EFFORT` *(необяз.)* — усилие модели, по умолчанию `low`;
   - `METRIKA_ACCURACY` *(необяз.)* — точность выборки, по умолчанию `medium`
     (`full` точнее, но над сезоном считается очень долго и может упереться
     в лимит времени функции);
   - `METRIKA_TIMEOUT` *(необяз.)* — таймаут запроса к Метрике, сек (по умолчанию 50);
   - `METRIKA_CONCURRENCY` *(необяз.)* — число одновременных запросов к Метрике
     (по умолчанию 2; Метрика лимитирует параллельные запросы, повышать осторожно);
   - `METRIKA_RETRIES` *(необяз.)* — ретраи на 429/5xx (по умолчанию 5).
3. Deploy. Форма будет на корневом URL, функция — на `/api/generate`.

> На Vercel у функции обычный исходящий интернет, поэтому Яндекс.Метрика
> доступна (в отличие от изолированной песочницы разработки).

На форме два режима (вкладки): **API Метрики** (выбор периода) и
**CSV-выгрузки** (загрузка файлов, экспортированных из интерфейса Метрики).
CSV-режим не требует токена Метрики и не упирается в лимиты API — нужен только
`ANTHROPIC_API_KEY` для текста.

Локальный запуск веб-версии: `vercel dev` (нужен Vercel CLI).

## Структура проекта

```
src/yandex_report/
  config.py          # чтение .env (Метрика + Anthropic + модель)
  metrika_client.py  # клиент Reporting API Метрики
  report_data.py     # запросы + агрегация по разделам (DataBlock)
  structure.py       # СТРУКТУРА отчёта: разделы, заголовки, примеры стиля
  report_writer.py   # генерация текста разделов через Claude (+ параллельно)
  docx_builder.py    # сборка нового .docx (в файл или в память)
  cli.py             # точка входа CLI
api/generate.py      # serverless-функция Vercel
public/index.html    # веб-форма
vercel.json          # конфигурация Vercel
samples/             # образец отчёта, из которого взята структура
tests/               # тесты на сбор данных, сборку docx и веб-функцию
```

## Как менять структуру или стиль

Всё — в `src/yandex_report/structure.py`:

- **порядок и заголовки разделов** — список `SECTIONS`;
- **о чём писать** в разделе — поле `guidance`;
- **тональность** — поле `style_example` (абзац-образец, который Claude берёт
  как ориентир по манере, не копируя факты);
- **какие данные** питают раздел — поле `data_key` (собирается в `report_data.collect`).

## Ограничения

Яндекс.Метрика покрывает **интернет-сайты** КХЛ (Приложение №1). Разделы
образца по мобильному приложению (AppMetrica / Google Analytics) и по Клубам
КХЛ (отдельные счётчики) требуют других источников и в этот отчёт не входят —
их можно добавить, расширив `structure.py` и `report_data.py`.
